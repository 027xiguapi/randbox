**Mathematical Principles**
The core of 1-100 random number generators is uniform distribution. Theoretically, each number has a 1/100 = 1% chance of being selected. But theory is rosy, reality is harsh - many "pseudo-random" generators can't achieve true uniform distribution.

function generateRandom1to100() {

### Q1: Are the generated numbers truly random?
**A**: This depends on the situation.

- **Ordinary scenarios** (games, lottery): use pseudo-random number generators (PRNG), good enough
- **Financial, security scenarios**: need cryptographically secure random number generators (CSPRNG)
- **High-end scenarios**: quantum random number generators (QRNG), but not yet popularized

- **Android Chrome**: average loading time 1.2 seconds, slight lag
- **WeChat built-in browser**: best performance, loading only 0.8 seconds

Suggest choosing tools with responsive design, adapting to various screen sizes.

### Q3: Can exclude certain numbers?
**A**: Advanced versions can!

**Common Needs**:
- Exclude unlucky numbers (4, 13, etc.)
- Exclude used numbers (non-repeating lottery)
- Custom weights (certain numbers have higher probability)

**Technical Implementation**: Use arrays to store candidate numbers, randomly select index, not directly generate numbers. This can precisely control each number's appearance probability.

### Q4: Why do continuous refreshes get the same result?
**A**: This is not a bug, it's a feature!

Some users feedback: "I refreshed several times, why are the numbers the same?" Actually this is to prevent users from "gaming the random number." Correct approach:
- After each generation, wait at least 30 seconds
- Or click "new group" button instead of refreshing page
- Good tools record your operations to prevent malicious refresh

### Q5: Can random numbers be predicted?
**A**: Depends on the algorithm.

- **Linear Congruential Method (LCG)**: predictable, someone once cracked online lottery using LCG
- **Mersenne Twister (MT19937)**: partially predictable, mathematicians have cracked its internal state
- **Cryptographically secure PRNG**: theoretically unpredictable, but actual implementation may have problems

**Suggestion**: Use CSPRNG for important scenarios, avoid LCG and ordinary MT19937.

### Q6: Will generated numbers repeat?
**A**: Depends on needs.

- **Lottery mode**: repeat allowed by default, each is independent event
- **Sampling mode**: can set to non-repeating, similar to shuffle algorithm
- **Weight mode**: certain numbers have higher probability, but may still repeat

**My suggestion**: Unless specified, allowing repeat is fairer in most scenarios.

### Q7: How to verify random number generator quality?
**A**: I use this "three-step verification method":

1. **Frequency test**: generate 10000 times, count each number's appearance, deviation should be within ±5%
2. **Sequence test**: check distribution patterns of consecutive numbers, look for periodicity
3. **NIST test**: run official randomness test suite, pass at least 12 items

**Simple self-test**: If you generate 100 times consecutively and find a number appears >20 times or &lt;5 times, something is wrong.

### Q8: Can random number generators be cracked?
**A**: Yes, but difficult.

**Common Attack Methods**:
- **Seed guessing**: if seed is predictable, entire sequence is predictable
- **Timestamp attack**: using regularity of timestamps as seeds
- **Side-channel attack**: infer random numbers by observing system behavior

**Protection Measures**:
- Use cryptographically secure algorithms
- Mix multiple entropy sources (time, system noise, network latency)
- Regularly change seeds
- Use HTTPS and CSP headers in Web applications
